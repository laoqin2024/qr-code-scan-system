## 🎯 解决的问题

### 1. 前端启动方式疑问

**问题：** 用户发现 PM2 只启动了后端服务，不清楚前端是如何启动的。

**解答：**
- 前端不是通过 PM2 启动的
- 前端通过 `npm run build` 构建成静态文件（`frontend/dist`）
- Nginx 直接提供静态文件服务
- Nginx 将 `/api` 请求代理到后端服务（PM2 管理）

**架构说明：**
```
用户请求
    ↓
Nginx (端口 80/443)
    ├─→ / (静态文件) → frontend/dist/
    └─→ /api (代理) → 后端服务 (PM2, 端口 3001)
```

### 2. 数据库初始化失败

**问题：** 自动部署脚本执行时报错：
```
❌ 初始化失败: UNIQUE constraint failed: users.username
```

**原因：** 数据库已存在数据，再次运行初始化脚本时尝试插入重复的用户名。

**解决方案：**

#### 方案 A：修复初始化脚本（已实现）
- 添加幂等性检查：运行前检查是否已有数据
- 如果已有数据，自动跳过初始化
- 提示用户如需重新初始化，需先删除数据库文件

#### 方案 B：提供预置数据库文件（已实现）
- 创建 `db.sqlite.init` 作为初始化模板
- 部署时优先使用预置文件（快速、可靠）
- 如果预置文件不存在，才运行初始化脚本
- 更新 `.gitignore` 允许提交 `db.sqlite.init`

### 3. 缺少项目更新方案

**问题：** 用户不知道如何更新已部署的项目。

**解决方案：** 创建完整的更新部署方案（见下文）。

### 2. scripts/deploy.sh

**修改内容：**
```bash

if [ -f "$INSTALL_DIR/db.sqlite.init" ]; then
    print_info "使用预初始化的数据库文件..."
    cp "$INSTALL_DIR/db.sqlite.init" "$INSTALL_DIR/db.sqlite"
    print_success "数据库初始化完成（使用预置文件）"
```

## ⚠️ 注意事项

### 部署时

1. **数据库初始化**
   - 优先使用预置文件 `db.sqlite.init`
   - 如果数据库已存在，会询问是否重新初始化
   - 重新初始化会删除所有数据

2. **前端启动**
   - 前端是静态文件，由 Nginx 提供服务
   - PM2 只管理后端服务
   - 前端更新后无需重启服务

### 更新时

1. **备份数据库**
   - 更新脚本会自动备份
   - 手动更新时务必先备份
   - 保留至少一周的备份

2. **依赖更新**
   - 更新脚本会智能检测依赖变化
   - 仅在 package.json 变化时才重新安装
   - 节省时间和带宽

3. **服务重启**
   - 更新脚本会自动重启服务
   - 支持 PM2、systemd、手动启动
   - 重启前会显示当前状态

### 回滚时

1. **代码回滚**
   - 使用 `git reset --hard` 回滚代码
   - 记录当前版本号以便恢复

2. **数据库恢复**
   - 从 backups 目录恢复备份
   - 确保备份文件完整

3. **重新构建**
   - 回滚后需要重新构建前端
   - 重启后端服务
