# 查看者权限优化方案

## 📋 问题分析

### 当前问题
- 客户管理员创建了查看者账号 qx002
- qx002 登录后看不到任何记录
- 原因：viewer 需要先被授权产品才能查看记录
- 缺少便捷的授权界面

### 根本原因
```typescript
// viewer 的查询逻辑
if (user.role === 'viewer') {
  // 只能看授权产品的记录
  query += ` AND s.product_id IN (
    SELECT product_id FROM user_product_permissions
    WHERE user_id = ? AND can_view = 1
  )`;
}
```

**问题：** 新创建的 viewer 没有任何产品权限，所以看不到任何记录。

---

## 🎯 优化方案

### 方案A：自动授权（推荐）

**核心思路：** 创建 viewer 时，自动授权创建者有权限的所有产品

**优点：**
- ✅ 用户体验好，创建后立即可用
- ✅ 实现简单
- ✅ 符合直觉

**实现：**

#### 1. 修改用户创建接口

```typescript
// backend/src/routes/users.ts
router.post('/', requireCustomerAdmin, async (req, res) => {
  // ... 创建用户逻辑
  
  // 如果是 viewer 或 operator，自动授权产品
  if (role === 'viewer' || role === 'operator') {
    // 获取创建者有权限的所有产品
    let products = [];
    
    if (user.role === 'super_admin') {
      // super_admin 创建的用户，授权所有产品
      products = db.prepare('SELECT id FROM products').all();
    } else if (user.role === 'customer_admin') {
      if (user.customer_id) {
        // 授权创建者客户的所有产品
        products = db.prepare('SELECT id FROM products WHERE customer_id = ?').all(user.customer_id);
      } else {
        // 授权创建者有权限的所有产品
        products = db.prepare(`
          SELECT DISTINCT product_id as id FROM user_product_permissions
          WHERE user_id = ?
        `).all(user.id);
      }
    }
    
    // 批量授权
    const stmt = db.prepare(`
      INSERT INTO user_product_permissions (user_id, product_id, can_scan, can_view, created_at)
      VALUES (?, ?, ?, ?, datetime('now'))
    `);
    
    for (const product of products) {
      const canScan = role === 'operator' ? 1 : 0;
      stmt.run(result.lastInsertRowid, product.id, canScan, 1);
    }
    
    // 记录审计日志
    db.prepare(`
      INSERT INTO audit_logs (user_id, action, resource_type, resource_id, details, created_at)
      VALUES (?, 'auto_grant_permissions', 'permission', ?, ?, datetime('now'))
    `).run(user.id, result.lastInsertRowid, JSON.stringify({ 
      product_count: products.length,
      role 
    }));
  }
  
  res.json({ id: result.lastInsertRowid });
});
```

### 方案B：创建时选择授权（灵活）

**核心思路：** 创建用户时，让管理员选择要授权的产品

**优点：**
- ✅ 灵活，可以精确控制
- ✅ 符合安全最佳实践

**实现：**

#### 1. 前端创建用户表单

```tsx
// frontend/src/pages/Users.tsx
const [formData, setFormData] = useState({
  username: '',
  password: '',
  display_name: '',
  role: 'operator' as UserRole,
  customer_id: '',
  auto_grant_products: true,  // 新增：是否自动授权
  selected_products: [] as number[],  // 新增：选择的产品
});

// 表单中添加
{(formData.role === 'operator' || formData.role === 'viewer') && (
  <div className="form-group">
    <label>
      <input
        type="checkbox"
        checked={formData.auto_grant_products}
        onChange={e => setFormData({ 
          ...formData, 
          auto_grant_products: e.target.checked 
        })}
      />
      自动授权所有产品
    </label>
    
    {!formData.auto_grant_products && (
      <div className="product-selector">
        <label>选择授权的产品：</label>
        {products.map(p => (
          <label key={p.id}>
            <input
              type="checkbox"
              checked={formData.selected_products.includes(p.id)}
              onChange={e => {
                if (e.target.checked) {
                  setFormData({
                    ...formData,
                    selected_products: [...formData.selected_products, p.id]
                  });
                } else {
                  setFormData({
                    ...formData,
                    selected_products: formData.selected_products.filter(id => id !== p.id)
                  });
                }
              }}
            />
            {p.model} ({p.customer_name})
          </label>
        ))}
      </div>
    )}
  </div>
)}
```

### 方案C：默认查看所有（最简单）

**核心思路：** viewer 默认可以查看所有记录，不需要授权

**优点：**
- ✅ 最简单
- ✅ 用户体验最好

**缺点：**
- ⚠️ 安全性较低
- ⚠️ 不符合细粒度权限控制

**实现：**

```typescript
// backend/src/routes/scans.ts
} else if (user.role === 'viewer') {
  // viewer 可以看所有记录（如果有 customer_id，只看该客户的）
  if (user.customer_id) {
    query += ' AND s.customer_id = ?';
    params.push(user.customer_id);
  }
  // 否则可以看所有记录
}
```

### 方案D：创建后提示授权（引导式）

**核心思路：** 创建用户后，提示管理员进行授权

**优点：**
- ✅ 不改变现有逻辑
- ✅ 引导用户正确操作

**实现：**

```tsx
// frontend/src/pages/Users.tsx
const handleSubmit = async (e: React.FormEvent) => {
  // ... 创建用户
  
  if (!editingUser && (formData.role === 'viewer' || formData.role === 'operator')) {
    // 创建成功后提示
    if (confirm(`用户创建成功！\n\n是否现在为该用户授权产品？\n（不授权的话，用户将无法查看任何记录）`)) {
      // 跳转到权限配置页面
      navigate(`/users/${newUserId}/permissions`);
    }
  }
};
```

## 💡 推荐方案

### 推荐：方案A（自动授权）+ 方案D（提示）

**实施步骤：**

1. **自动授权**：创建 viewer/operator 时，自动授权创建者有权限的所有产品
2. **成功提示**：创建后显示授权了多少个产品

```

5. 如需调整，可以在权限管理中修改
```
