# 扫码录入系统 - 权限管理方案

## 一、业务场景分析

### 典型使用场景
1. **多客户并行**：同一时间多个客户的产品在不同工位扫码
2. **数据隔离**：客户A的操作员不能看到客户B的数据
3. **权限分级**：管理员、客户管理员、操作员、查看者
4. **审计追溯**：记录谁在什么时间扫描了什么产品

## 二、角色权限设计

### 角色定义

| 角色 | 代码 | 权限范围 |
|------|------|----------|
| 超级管理员 | `super_admin` | 系统全局管理，用户管理，所有数据 |
| 客户管理员 | `customer_admin` | 管理指定客户的产品和操作员 |
| 操作员 | `operator` | 扫码录入指定产品，查看自己的记录 |
| 查看者 | `viewer` | 只读查看指定客户/产品的记录 |

### 权限矩阵

| 功能模块 | super_admin | customer_admin | operator | viewer |
|---------|-------------|----------------|----------|--------|
| 用户管理 | ✅ 全部 | ✅ 本客户操作员 | ❌ | ❌ |
| 客户管理 | ✅ 增删改查 | ✅ 查看本客户 | ❌ | ❌ |
| 产品管理 | ✅ 增删改查 | ✅ 本客户产品 | ❌ | ❌ |
| 扫码录入 | ✅ 所有产品 | ✅ 本客户产品 | ✅ 授权产品 | ❌ |
| 记录查询 | ✅ 所有记录 | ✅ 本客户记录 | ✅ 自己的记录 | ✅ 授权范围 |
| 数据导出 | ✅ 所有 | ✅ 本客户 | ❌ | ✅ 授权范围 |

## 三、数据库设计

### 新增表结构

```sql
-- 1. 用户表扩展（添加客户关联）
ALTER TABLE users ADD COLUMN customer_id INTEGER REFERENCES customers(id);
ALTER TABLE users ADD COLUMN is_active INTEGER DEFAULT 1;
ALTER TABLE users ADD COLUMN last_login TEXT;

-- 2. 用户-产品授权表（操作员可以扫哪些产品）
CREATE TABLE user_product_permissions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  product_id INTEGER NOT NULL,
  can_scan INTEGER DEFAULT 1,
  can_view INTEGER DEFAULT 1,
  created_at TEXT NOT NULL,
  FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY(product_id) REFERENCES products(id) ON DELETE CASCADE,
  UNIQUE(user_id, product_id)
);

-- 3. 扫码记录添加操作员字段
ALTER TABLE scans ADD COLUMN user_id INTEGER REFERENCES users(id);

-- 4. 操作日志表（审计用）
CREATE TABLE audit_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  action TEXT NOT NULL,
  resource_type TEXT NOT NULL,
  resource_id INTEGER,
  details TEXT,
  ip_address TEXT,
  created_at TEXT NOT NULL,
  FOREIGN KEY(user_id) REFERENCES users(id)
);
```

## 四、权限检查逻辑

### 1. 中间件层级

```typescript
// 权限检查流程
请求 → JWT验证 → 角色检查 → 数据权限检查 → 业务逻辑
```

### 2. 数据权限过滤

**超级管理员**：无过滤，访问所有数据

**客户管理员**：
```sql
WHERE customer_id = user.customer_id
```

**操作员**：
```sql
-- 扫码录入：只能扫授权的产品
WHERE product_id IN (
  SELECT product_id FROM user_product_permissions 
  WHERE user_id = ? AND can_scan = 1
)

-- 查询记录：只能看自己扫的
WHERE user_id = ?
```

**查看者**：
```sql
WHERE product_id IN (
  SELECT product_id FROM user_product_permissions 
  WHERE user_id = ? AND can_view = 1
)
```

## 五、API 接口设计

### 用户管理接口

```
POST   /api/users              创建用户（super_admin）
GET    /api/users              用户列表（按权限过滤）
PUT    /api/users/:id          更新用户
DELETE /api/users/:id          删除用户
POST   /api/users/:id/activate 激活/停用用户
```

### 权限管理接口

```
GET    /api/users/:id/permissions           获取用户权限
POST   /api/users/:id/permissions/products  授权产品
DELETE /api/users/:id/permissions/products/:productId  撤销授权
GET    /api/products/:id/users              查看产品的授权用户
```

### 审计日志接口

```
GET    /api/audit-logs         审计日志（管理员）
GET    /api/audit-logs/my      我的操作记录
```

## 七、安全加固

### 1. 密码策略
- 最小长度 8 位
- 必须包含字母+数字
- 定期提醒修改密码

### 2. 会话管理
- JWT 有效期 8 小时
- 支持强制下线
- 记录登录IP和时间

### 3. 操作审计
- 记录所有增删改操作
- 记录登录/登出
- 敏感操作二次确认

### 4. 数据脱敏
- 导出数据时脱敏处理
- 日志中不记录敏感信息

## 九、使用示例

### 场景1：新增客户和操作员

```
1. super_admin 创建客户 "富士康"
2. super_admin 创建 customer_admin "张经理"，关联到 "富士康"
3. 张经理 创建产品 "iPhone 15"
4. 张经理 创建 operator "李师傅"
5. 张经理 授权 "李师傅" 可以扫 "iPhone 15"
6. 李师傅 登录后只能看到 "iPhone 15"，开始扫码
```

### 场景2：多客户并行

```
工位1: 操作员A（客户：富士康） → 扫 iPhone 15
工位2: 操作员B（客户：比亚迪） → 扫 电池模组
工位3: 操作员C（客户：富士康） → 扫 iPad Pro

操作员A 看不到 操作员B 的数据
操作员A 和 C 可以看到同一客户的产品，但只能看到自己扫的记录
```
