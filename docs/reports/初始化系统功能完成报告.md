## 🔧 技术实现

### 后端实现

**文件：** `backend/src/routes/scans.ts`

#### 初始化系统接口

```typescript
router.post('/initialize-system', requireAuth, async (req: AuthRequest, res) => {
  // 权限检查：只有超级管理员可以初始化
  if (user.role !== 'super_admin') {
    return res.status(403).json({ error: '只有超级管理员可以初始化系统' });
  }
  
  const db = getDb();
  db.exec('BEGIN TRANSACTION');
  
  try {
    // 1. 删除所有扫码记录
    db.prepare('DELETE FROM scans').run();
    
    // 2. 删除所有权限记录
    db.prepare('DELETE FROM user_product_permissions').run();
    
    // 3. 将所有用户的 customer_id 设为 NULL（先解除对客户的引用）
    db.prepare('UPDATE users SET customer_id = NULL').run();
    
    // 4. 将所有产品的 created_by 设为 NULL
    db.prepare('UPDATE products SET created_by = NULL').run();
    
    // 5. 删除所有产品
    db.prepare('DELETE FROM products').run();
    
    // 6. 将所有客户的 created_by 设为 NULL
    db.prepare('UPDATE customers SET created_by = NULL').run();
    
    // 7. 删除所有客户
    db.prepare('DELETE FROM customers').run();
    
    // 8. 删除所有审计日志
    db.prepare('DELETE FROM audit_logs').run();
    
    // 9. 将所有用户的 created_by 设为 NULL
    db.prepare('UPDATE users SET created_by = NULL').run();
    
    // 10. 删除除 admin 外的所有用户
    db.prepare('DELETE FROM users WHERE id != 1').run();
    
    // 11. 重置 admin 的状态
    db.prepare(`
      UPDATE users 
      SET is_active = 1, 
          last_login = NULL,
          customer_id = NULL,
          created_by = NULL
      WHERE id = 1
    `).run();
    
    db.exec('COMMIT');
    
    res.json({ 
      message: '系统初始化完成',
      deleted_scans: allScans.count,
      deleted_products: allProducts.count,
      deleted_customers: allCustomers.count,
      deleted_users: allUsers.count,
      deleted_permissions: allPermissions.count,
      deleted_audit_logs: allAuditLogs.count
    });
  } catch (error) {
    db.exec('ROLLBACK');
    throw error;
  }
});
```

## 📊 删除顺序

### 正确的删除顺序（避免外键约束）

```
1. 删除扫码记录（scans）
   - 不被其他表引用

2. 删除权限记录（user_product_permissions）
   - 不被其他表引用

3. 解除用户对客户的引用（users.customer_id → NULL）
   - 避免删除客户时外键约束失败

4. 解除产品的创建者引用（products.created_by → NULL）
   - 避免删除用户时外键约束失败

5. 删除产品（products）
   - 被 scans 和 permissions 引用（已删除）

6. 解除客户的创建者引用（customers.created_by → NULL）
   - 避免删除用户时外键约束失败

7. 删除客户（customers）
   - 被 products 和 users 引用（已处理）

8. 删除审计日志（audit_logs）
   - 引用 users，但不阻止删除

9. 解除用户的创建者引用（users.created_by → NULL）
   - 避免自引用导致删除失败

10. 删除用户（users WHERE id != 1）
    - 保留 admin

11. 重置 admin 状态
    - is_active = 1
    - customer_id = NULL
    - created_by = NULL
    - last_login = NULL
```

## 💡 设计原则

### 1. 安全性

**权限控制：**
- ✅ 只有超级管理员可以初始化
- ✅ 其他角色无权访问

**二次确认：**
- ✅ 第一次确认：说明操作内容
- ✅ 第二次确认：强调危险性
- ✅ 防止误操作

**保留管理员：**
- ✅ 保留 admin 账号（ID=1）
- ✅ 确保系统始终可登录
- ✅ 避免系统锁死

### 2. 数据一致性

**使用事务：**
```typescript
db.exec('BEGIN TRANSACTION');
try {
  // 所有删除操作
  db.exec('COMMIT');
} catch (error) {
  db.exec('ROLLBACK');
  throw error;
}
```

**优势：**
- ✅ 要么全部成功，要么全部失败
- ✅ 不会留下部分删除的数据
- ✅ 数据一致性有保证

### 3. 外键处理

**正确处理外键约束：**
- ✅ 先解除引用，再删除数据
- ✅ 按正确顺序删除
- ✅ 不禁用外键检查

**关键步骤：**
1. 先将 `users.customer_id` 设为 NULL
2. 再将 `products.created_by` 设为 NULL
3. 再将 `customers.created_by` 设为 NULL
4. 再将 `users.created_by` 设为 NULL
5. 最后删除数据

### 4. 可恢复性

**重置 admin 状态：**
```sql
UPDATE users 
SET is_active = 1, 
    last_login = NULL,
    customer_id = NULL,
    created_by = NULL
WHERE id = 1
```

**确保：**
- ✅ admin 账号处于激活状态
- ✅ 没有任何引用
- ✅ 可以正常登录和使用
