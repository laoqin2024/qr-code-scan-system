# 权限系统优化方案 - 多客户多产品支持

## 一、需求分析

### 当前问题
1. 用户表中 `customer_id` 字段限制了用户只能属于一个客户
2. 操作员只能操作自己客户的产品
3. 无法实现跨客户的产品授权

### 优化目标
1. 操作员可以被授权多个客户的多个产品
2. 客户管理员可以管理多个客户
3. 权限完全基于产品授权，而不是客户归属

## 二、数据库优化

### 方案A：移除 customer_id 限制（推荐）

**优点：**
- 简单直接
- 完全基于产品授权
- 灵活性最高

**实现：**
```sql
-- 1. customer_id 改为可选（用于默认客户，方便管理）
-- 2. 权限完全由 user_product_permissions 表控制
-- 3. 操作员可以被授权任意客户的任意产品
```

### 方案B：用户-客户关联表

**优点：**
- 可以明确管理用户可以访问哪些客户
- 便于批量授权（授权整个客户的所有产品）

**实现：**
```sql
CREATE TABLE user_customer_permissions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  customer_id INTEGER NOT NULL,
  can_manage INTEGER DEFAULT 0,  -- 是否可以管理该客户
  created_at TEXT NOT NULL,
  FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY(customer_id) REFERENCES customers(id) ON DELETE CASCADE,
  UNIQUE(user_id, customer_id)
);
```

## 三、推荐实现（方案A）

### 1. 数据库调整

**users 表：**
- `customer_id` 保留但改为可选
- 仅用于标识"默认客户"或"主要负责客户"
- 不再用于权限控制

**权限控制逻辑：**
```typescript
// 旧逻辑（基于客户归属）
if (user.role === 'operator' && product.customer_id !== user.customer_id) {
  return 403; // 无权限
}

// 新逻辑（基于产品授权）
const permission = db.query(
  'SELECT * FROM user_product_permissions WHERE user_id = ? AND product_id = ?',
  [user.id, product.id]
);
if (!permission || !permission.can_scan) {
  return 403; // 无权限
}
```

### 2. 角色定义调整

#### super_admin（超级管理员）
- 无变化
- 可以管理所有客户、产品、用户

#### customer_admin（客户管理员）
- **旧**：只能管理一个客户
- **新**：可以管理多个客户（通过授权）
- 可以为操作员授权自己管理的客户的产品

#### operator（操作员）
- **旧**：只能操作一个客户的产品
- **新**：可以操作多个客户的产品（通过授权）
- 完全基于产品授权列表

#### viewer（查看者）
- **旧**：只能查看一个客户的记录
- **新**：可以查看多个客户的记录（通过授权）

### 3. API 调整

#### 获取用户可访问的客户列表
```typescript
GET /api/users/:id/customers

// 返回用户有权限访问的所有客户
// 基于 user_product_permissions 表关联查询
```

#### 获取用户可访问的产品列表
```typescript
GET /api/users/:id/products

// 返回用户有权限访问的所有产品
// 直接从 user_product_permissions 表查询
```

#### 批量授权客户的所有产品
```typescript
POST /api/users/:id/permissions/customers/:customerId/products

// 将某个客户的所有产品授权给用户
```

## 四、实施步骤

### Step 1: 数据库迁移
```sql
-- 1. customer_id 改为可选（已经是可选）
-- 2. 添加辅助查询视图
CREATE VIEW user_accessible_customers AS
SELECT DISTINCT u.id as user_id, p.customer_id
FROM users u
JOIN user_product_permissions upp ON u.id = upp.user_id
JOIN products p ON upp.product_id = p.id;

CREATE VIEW user_accessible_products AS
SELECT u.id as user_id, p.*
FROM users u
JOIN user_product_permissions upp ON u.id = upp.user_id
JOIN products p ON upp.product_id = p.id;
```

### Step 2: 后端接口调整
- 移除基于 customer_id 的权限检查
- 改为基于 user_product_permissions 的检查
- 添加批量授权接口

### Step 3: 前端界面调整
- 用户管理：customer_id 改为可选
- 权限配置：支持跨客户授权产品
- 产品选择：显示所有可授权的产品（不限客户）

## 五、使用场景示例

### 场景1：跨客户操作员
```
操作员张三：
- 授权产品：
  * 富士康 - iPhone 15
  * 富士康 - iPad Air
  * 比亚迪 - 电池模组
  * 华为 - 5G基站

张三可以在同一个扫码界面切换不同客户的产品进行扫码
```

### 场景2：多客户管理员
```
客户管理员李四：
- 管理客户：富士康、比亚迪
- 可以为操作员授权这两个客户的任意产品
- 可以查看这两个客户的所有扫码记录
```

### 场景3：临时授权
```
操作员王五：
- 平时只扫富士康的产品
- 临时需要帮忙扫比亚迪的产品
- 管理员临时授权比亚迪的产品给王五
- 完成后可以撤销授权
```
