## 🎯 实施方案（已完成）

### ✅ 方案A：基于创建者的所有权（已采用）

#### 核心概念
- 每个客户记录关联创建者（created_by）
- 每个产品记录关联创建者（created_by）
- 扫码记录已有 user_id（录入人）

#### 权限规则

**客户管理：**
```
查看权限：
- super_admin: 所有客户
- customer_admin: 所有客户（只读）
- customer_admin: 自己创建的客户（可编辑）

编辑权限：
- super_admin: 所有客户
- customer_admin: 仅自己创建的客户

删除权限：
- super_admin: 所有客户
- customer_admin: 仅自己创建的客户（且无关联数据）
```

**产品管理：**
```
查看权限：
- super_admin: 所有产品
- customer_admin: 所有产品
- operator: 授权的产品

编辑权限：
- super_admin: 所有产品
- customer_admin: 自己创建的产品

删除权限：
- super_admin: 所有产品
- customer_admin: 自己创建的产品（且无扫码记录）
```

**扫码记录：**
```
显示字段：
- 客户名称
- 产品型号
- 二维码内容
- 录入人员（username）
- 录入时间
- 是否有效

查询权限：
- super_admin: 所有记录
- customer_admin: 所有记录
- operator: 自己录入的记录
- viewer: 授权产品的记录
```

#### 数据库设计 ✅ 已实施

```sql
-- 1. 用户表添加真实姓名
ALTER TABLE users ADD COLUMN display_name TEXT;

-- 2. 客户表添加创建者
ALTER TABLE customers ADD COLUMN created_by INTEGER REFERENCES users(id);

-- 3. 产品表添加创建者
ALTER TABLE products ADD COLUMN created_by INTEGER REFERENCES users(id);

-- 4. 扫码记录已有 user_id（录入人）
-- scans.user_id 已存在

-- 5. 创建索引
CREATE INDEX idx_users_display_name ON users(display_name);
CREATE INDEX idx_customers_created_by ON customers(created_by);
CREATE INDEX idx_products_created_by ON products(created_by);
```

**迁移脚本：** `backend/src/migrate-v3.ts`  
**备份文件：** `db.sqlite.backup-v3`

#### 优点
✅ 清晰的所有权概念
✅ 防止误操作他人数据
✅ 便于数据追溯
✅ 符合多租户场景

#### 缺点
⚠️ 需要数据库迁移
⚠️ 现有数据需要补充创建者信息

### 方案B：基于客户归属的权限（备选）

#### 核心概念
- 客户管理员必须关联一个或多个客户
- 只能管理自己关联的客户
- 通过 user_customer_permissions 表管理

#### 权限规则

**客户管理：**
```
查看权限：
- super_admin: 所有客户
- customer_admin: 所有客户（只读）
- customer_admin: 关联的客户（可编辑）

编辑权限：
- super_admin: 所有客户
- customer_admin: 仅关联的客户
```

#### 数据库设计

```sql
-- 用户-客户关联表
CREATE TABLE user_customer_permissions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  customer_id INTEGER NOT NULL,
  can_manage INTEGER DEFAULT 0,  -- 是否可以管理
  created_at TEXT NOT NULL,
  FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY(customer_id) REFERENCES customers(id) ON DELETE CASCADE,
  UNIQUE(user_id, customer_id)
);
```

#### 优点
✅ 灵活的权限分配
✅ 支持多客户管理
✅ 可以转移管理权

#### 缺点
⚠️ 复杂度较高
⚠️ 需要额外的权限配置界面
⚠️ 创建客户时需要自动关联
